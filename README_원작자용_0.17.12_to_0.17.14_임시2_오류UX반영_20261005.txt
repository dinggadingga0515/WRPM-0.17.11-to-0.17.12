Wish RP Manager 0.17.12 → 0.17.14(임시2)
원작자 READ용 쉬운 설명판
작성일: 2026-10-05

원작자가 .12와 .14의 차이를 빠르게 파악할 수 있도록
“무엇을 바꿨는지 / 왜 바꿨는지 / 기존 기능은 무엇을 유지했는지”를 정리했습니다.

함수 이름과 코드 반영 방법은 별도 AI 인수인계 문서에 있습니다.
이 문서는 실제 사용 중 달라지는 점을 중심으로 설명합니다.

1. 30초 요약
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

.14는 원작자 .12를 기준으로 다음 부분을 보완한 버전입니다.

1) Quick Monitor에서 현재 넣지 않은 캐릭터·OOC 자료도 임시로 추가할 수 있음
2) Quick Monitor에서 뺐다가 다시 넣은 자료의 선택과 남은 유지턴을 제대로 유지
3) 평소 체크를 꺼 둔 캐릭터도 RP에 등장하면 자동으로 넣는 선택사항 추가
4) 강조색과 배경색을 고르고, 그 색에 맞춰 화면의 밝고 어두운 색을 함께 조절
5) 결과를 기다리는 동안 RP를 이어가거나 메모를 바꿨을 때 불필요한 작업 중단 감소
6) 여러 기억을 한꺼번에 반영할 때 최신 선택과 편집 내용을 보존
7) 다른 작업의 결과를 잘못 넣는 문제와, 반영·복구 실패를 놓치는 문제 보완
8) 빨간 오류 표시를 누르거나 올리면 원인·오류 원문·간단한 해결 방법을 바로 확인

전체 방향은 다음과 같습니다.

“현재 주입은 더 편하게 조절하고,
정상적으로 RP를 이어간 변화는 보존하며,
원문이나 실제 반영 대상이 달라졌다면 적용 전에 다시 확인한다.”

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 가장 큰 변화 ① — Quick Monitor에서 필요한 자료를 바로 추가
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Quick Monitor는 현재 주입할 자료를 작은 창에서 확인하고 켜거나 끄는 기능입니다.
여기서 ‘주입’은 캐릭터 설정이나 기억 같은 자료를 AI가 참고하도록 넣는 것을 뜻합니다.

.14에서는 저장해 둔 캐릭터나 OOC 자료가 현재 주입 목록에 없어도
Quick Monitor에서 바로 추가할 수 있습니다.

예를 들어:
- 캐릭터 설정은 저장돼 있지만 메인 화면에서는 체크를 꺼 둠
- 최근 대화에 이름이 없어서 자동으로 선택되지 않음
- 사용자는 지금 그 캐릭터의 설정이 필요하다고 판단함

이때 Quick Monitor에서 추가하면 현재 주입에 임시로 넣을 수 있습니다.
메인 화면의 체크를 계속 켜 놓도록 바꾸는 것은 아닙니다.

이렇게 직접 추가한 캐릭터·OOC는 자동으로 목록을 정리하는 과정에서도 유지합니다.
반대로 Quick Monitor에서 임시로 뺀 자료는 자동 선택 때문에 곧바로 다시 들어오지 않도록 합니다.

또한 Quick Monitor 창을 사용하는 동안 항목의 위치와 묶음이 덜 흔들리도록 했고,
묶음별로 접어서 볼 수 있도록 했습니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. 가장 큰 변화 ② — 다시 추가한 자료와 유지턴 처리 보완
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

자료를 Quick Monitor에서 뺐다가 다시 넣었을 때도
‘사용자가 직접 선택한 자료’라는 뜻을 유지하도록 보완했습니다.

유지턴도 상태에 맞게 처리합니다.

예를 들어 5턴 동안 사용하는 자료라면:
- 3턴을 사용하고 2턴이 남음 → 다시 넣어도 남은 2턴을 유지
- 이미 5턴을 모두 사용함 → 다시 넣으면 새로 시작

이미 사용을 마친 자료를 다시 넣었는데도 끝난 상태로 남아
실제로는 주입되지 않는 문제를 고쳤습니다.

날짜로그나 자료집 검색 결과처럼 상황에 따라 바뀌는 자료는
각 자료의 기존 선택 규칙을 따릅니다.
캐릭터·OOC의 임시 선택 규칙을 모든 기억에 일괄 적용하지 않습니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 가장 큰 변화 ③ — 체크를 꺼 둔 캐릭터의 자동 선택
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

‘RP 등장 캐릭터 자동 선택’ 아래에 다음 선택사항을 추가했습니다.

“체크 해제 캐릭터도 자동 선택”

기본값은 OFF입니다. 기존 방을 열어도 자동으로 켜지지 않습니다.

[OFF일 때]
.12처럼 사용자가 메인 체크를 직접 끈 캐릭터는 자동으로 다시 선택하지 않습니다.

[ON일 때]
평소 메인 체크를 꺼 둔 캐릭터도 실제 RP에 등장하면 자동으로 넣을 수 있습니다.

예를 들어:
“이 캐릭터는 평소에는 넣지 않고, 등장하는 장면에서만 넣고 싶다.”
이런 사용법을 선택할 수 있게 했습니다.

함께 지키는 기준:
- 캐릭터별 ‘자동 선택 제외’를 켜 두면 이 선택사항이 ON이어도 자동으로 넣지 않음
- 직접 켠 캐릭터와 항상 주입으로 지정한 캐릭터는 기존 선택을 유지
- Quick Monitor에서 직접 추가한 자료는 별도로 유지
- 중요물품의 자동 선택에는 이 선택사항을 적용하지 않음

ON에서 OFF로 바꾸면, 자동 감지 때문에 켜져 있던 수동 OFF 캐릭터를 즉시 꺼 줍니다.
이 변경을 서버에도 반영하고, 도중에 실패하면 이전 선택으로 복구하도록 보완했습니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. 화면 색상을 고를 수 있게 개선
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

강조색과 배경색을 각각 고를 수 있습니다.

고른 색 하나로 모든 부분을 똑같이 칠하는 방식이 아니라,
그 색을 바탕으로 배경·카드·구분선 등의 밝고 어두운 색을 함께 만듭니다.

색상 선택은 저장하고 다시 사용할 수 있습니다.
색을 적용하고 해제하는 코드 검사는 통과했습니다.
실제 화면에서의 색상과 조작감은 별도 확인이 필요합니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. 결과를 기다리는 동안 RP를 이어가도 덜 막히도록 개선
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

전체 재구축이나 이어갱신은 작업자료를 만든 뒤 결과를 받기까지 시간이 걸릴 수 있습니다.
그동안 RP를 더 진행하거나 메모를 고치는 일도 있습니다.

.14에서는 이런 정상적인 변화를 실제 충돌과 구분합니다.

[RP를 더 진행한 경우]
기존 원문이 그대로이고 뒤에 새 대화만 추가됐다면 결과를 검토할 수 있습니다.
이번 작업자료에 들어 있지 않은 새 대화는 다음 갱신 대상으로 남깁니다.

[메모나 지침을 바꾼 경우]
변경됐다는 안내를 보여 주고, 현재 상태를 기준으로 다시 비교합니다.
받아 온 결과가 이전 메모·지침을 기준으로 만들어졌을 수 있다는 점도 알립니다.

[Quick Monitor에서 현재 넣을 자료를 바꾼 경우]
사용자가 방금 고른 현재 선택을 이전 상태로 덮어쓰지 않도록 합니다.

예를 들어:
“타임라인 결과를 기다리는 동안 Quick Monitor에서 캐릭터를 하나 추가했다.”
이 경우 타임라인을 반영하면서 새 캐릭터 선택도 보존하도록 했습니다.

다만 결과에 들어 있는 원문이나 작업 정보가 맞는지는 계속 확인합니다.
과거 RP를 고쳤거나 다른 방의 결과를 가져왔다면 적용을 막습니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. 여러 기억을 함께 반영할 때 최신 상태 보존
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

전체 재구축과 통합 이어갱신에서는
결과를 비교한 뒤 사용자가 고른 기억 영역만 반영합니다.

.14에서는 다음을 구분합니다.

- 사용자가 고르지 않은 기억을 나중에 수정함 → 그 수정은 보존
- 현재 넣을 자료의 선택만 바뀜 → 현재 선택을 보존
- 적용하려던 기억의 본문·설정·진행 기준이 바뀜 → 적용을 멈추고 다시 비교

결과가 ‘변경 없음’이라고 답한 영역도
정말 이전 기준과 맞는지 확인하도록 보완했습니다.

저장 직전과 저장 후 확인도 강화했습니다.
자료를 준비하는 동안 방이 바뀌거나 다른 저장이 끼어들면 그대로 덮어쓰지 않습니다.
저장 확인 중 사용자가 새로 편집한 내용도 보존하도록 했습니다.

저장 후 확인이 실패했을 때는 주의해서 안내합니다.
이미 저장됐을 수 있으므로 ‘아무것도 저장되지 않았다’고 단정하지 않습니다.
완료로 표시하지 않고 실제 저장 내용과 적용 전 백업을 확인하도록 합니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
8. 다른 작업의 결과를 잘못 넣는 문제 보완
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

외부 AI에게 작업자료를 주고 결과를 가져올 때,
그 결과가 지금 진행 중인 작업의 것인지 더 확실하게 확인합니다.

- 새로 만든 작업에는 작업 식별번호가 필요함
- 결과가 여러 파일이거나 번호가 여러 번 나오면 적힌 번호를 모두 확인
- 뒤쪽 파일에 다른 번호가 있어도 적용을 막음
- 번호 없이 쓰던 이전 작업자료는 기존 방식으로 읽을 수 있게 유지
- 이전 작업자료라도 잘못된 번호가 명시돼 있으면 적용을 막음

자료집 결과를 비교할 때와 실제 적용할 때도 같은 기준으로 입력을 처리합니다.
작업번호가 붙어 있거나 정상적인 텍스트 파일로 저장됐다는 이유만으로
같은 결과가 비교와 적용 단계에서 서로 다르게 판단되지 않도록 보완했습니다.

장기기억 작업도 긴 RP 조회를 끝낸 뒤 최신 기억 목록을 기준으로 준비합니다.
작업과 무관하게 새로 추가한 기억은 보존하고, 실제로 바꾸려던 기억의 충돌은 확인합니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
9. 자료압축과 실패 복구 보완
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[자료압축]
자동으로 감지한 시각이나 현재 선택 상태가 바뀐 것을
자료 본문 자체가 바뀐 것과 구분하도록 했습니다.

실제 본문, 사용자가 잠근 자료, 자료집 묶음의 사용 여부처럼 중요한 내용과 설정은

다만 일부 이전 작업자료에는 생성 당시 자료집 묶음의 사용 여부가 기록돼 있지 않습니다.

확인되지 않은 상태와 복구용 백업을 남깁니다.

[과거 오류가 계속 남는 문제]
AI 기능 상태는 이제
“그 오류가 발생했을 때의 제공자(provider) + 모델”과
현재 선택한 제공자 + 모델이 같을 때만 현재 상태로 인정합니다.

예를 들어:
- 이전 모델 A에서 오류 발생
- 모델 B로 변경
→ 모델 A의 빨간 오류를 모델 B의 현재 오류처럼 계속 표시하지 않음
→ B는 다시 확인하기 전까지 “확인 전”으로 취급

또한 AI 요약 창의 연결 테스트가 성공하면
메인 AI 상태에도 정상 결과를 저장하고,
실패하면 실패 종류와 실제 오류 문구를 저장하도록 보완했습니다.

이 도움말 기능은 오류를 자동으로 무시하거나
저장 실패를 강제로 재시도하는 기능이 아닙니다.
사용자 데이터 삭제·강제 덮어쓰기·자동 재저장 없이
현재 오류 상태와 확인 순서를 설명하는 용도로만 동작합니다.
