D. Quick / 캐릭터 정책 / carrier 복구
============================================================

autoCharacterIncludeUnchecked는 방별 필드이며 getRoom/normalizeRoomSlots에서 false 기본값이다. syncOpenModalIntoRoom/backupRoomSignature/renderModal, 감지와 주입 판정 경로를 함께 반영한다. checkbox만 추가하면 실제 정책 이식은 불완전하다.

OFF: manualInjectionOverride='off' 캐릭터 자동 재선택 금지, .12 동작 유지.
ON: character이고 RP 등장 근거가 있으며 autoExcluded가 아니면 메인 OFF라도 현재 자동선택 가능.
개별 자동선택 제외는 전역 ON보다 우선. manual ON/autoPinned 권한 유지. 미등장 시 자동 OFF 복귀.
Quick 강제선택은 별도 현재 pending 권한. item이나 모든 동적 기억의 자동선택 정책으로 새지 않음.

quickUninjectedSlotRows / applyQueuedQuickChanges:
- 새 임시추가뿐 아니라 quickRemovedItems에서 복원한 character/extra에도 quickManualInjection=true.
- 메인 enabled를 영구 ON으로 바꾸지 않는다.
- totalTurns>0 && usedTurns>=totalTurns일 때만 usedTurns=0. 진행 중 사용량과 무기한(totalTurns=0) 의미 유지.
- suppressed 항목은 즉시 자동 재추가하지 않음. pending/Quick rollback 유지.
- 날짜로그/자료집 검색/AI 산출물에 character/extra 수동 권한을 일괄 적용하지 않음.

ON→OFF handler:
이전 옵션·enabled·pending snapshot → 자동감지 때문에 켜진 manual OFF를 즉시 OFF → Quick 강제추가 유지 → carrier 동기화/로컬 저장.
실패하면 local snapshot 복구. 서버가 이미 반영되었거나 반영 가능성이 있으면 이전 carrier로 보상 sync.
syncPendingCarrierNow의 rpcmCarrierNeedsRollback 신호는 실제 쓰기 시도 후 실패/자체 rollback 검증 여부를 상위 handler에 전달한다.
복구 확인도 실패하면 verified=false / policyRollbackError / 복구 백업을 유지하고 성공으로 숨기지 않는다.

H. 외부 수동/자료집/장기기억 결과

신규 resultJobIdRequired job은 적어도 한 JOB_ID가 필요하다. 입력의 모든 명시 ID를 모아 현재 job과 대조한다. 여러 파일/줄 중 뒤의 다른 ID도 정상 import에서 거부한다. 각 파일에 반드시 별도 헤더를 요구하는 계약으로 바꾼 것은 아니다.

manualRawResultInputs에서 ID를 검사하고, manualResultInputs로 JOB_ID/BOM을 정규화하여 입력 내용 대조를 수행한다.

메모/current guide/휘발성 drift는 필요한 경고·현재값 재검토로 구분한다. 실제 대상/source/job/inventory conflict는 차단한다.
장기기억 inventory snapshot은 긴 RP read 뒤 최신 시점으로 이동했다. non-target 새 항목을 generation-era 목록으로 덮어쓰지 않는다.
최종 packet 600,000자 경계와 결과 안전 한도를 검사한다.
JSON Repair는 local syntax/schema를 고친 뒤 정상 parse→prepare→Diff→commit으로 돌아온다. source/hash/room/job/stale는 repair로 수용하지 않음. Hold 재개도 room/route/job guard를 유지한다.

[AI 상태 stale 방지]
aiFeatureCurrentStatus(settings, feature, providerOverride, modelOverride):
- 저장된 featureStatus는 status.provider/status.model이 현재 기능의 provider/model과 정확히 일치할 때만 유효하다.
- 모델 또는 제공자를 바꾸면 이전 모델의 ok/error를 현재 모델 상태로 재사용하지 않는다.
- 현재 모델에서 아직 검사하지 않았다면 메인 UI는 “확인 전”으로 돌아가야 한다.
- 기능별 API 설정의 상태 행과 메인 AI 상태 칩, itemFolder lastRun 판정도 이 경로를 사용한다.

[AI 요약 창 자체의 연결 테스트]
openAiSummaryDialog의 연결 테스트:
- 성공 시 setAiFeatureStatus('summary','ok', 실제 provider/model, ...)를 호출한다.
